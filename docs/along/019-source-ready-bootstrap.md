# First-ready continuation for legacy goals

Implementation: [source-goal-review.ts](../../src/along/source-goal-review.ts); durable metadata extends HealthStore/HealthFollowup. Migration 13 creates `source_goal_review`, linked to the existing durable `health_dispatch` outbox. Actual bridge acceptance calls `AlongService.acceptSourceEvent`: accepted metadata and a necessary review are committed atomically, before acknowledgement. Every runtime tick also reconciles old accepted ready facts, so an upgrade/restart cannot permanently miss the first event.

This compatibility path applies only to an active, owned, paired goal recommending OKX, whose actual accepted source has `trading_account_summary` ready and which has open tasks without typed triggers. Fully typed goals use normal TaskActivation. A completed review suppresses subsequent price revisions in that source grant; a pending review is reused for the same input. Work retries use the same Ticket and backoff. It is not a Worker per price update.

The non-human `source_review` mandate is a legitimate background event, never a fabricated user message. Its event/outbox contains grant metadata and original task boundaries, no private account summary. `along_source_review_context` reads the goal, original conversation/tasks and capability coverage; remaining pages use bound read tools. Three registered summary fields (USD equity and two counts) do not establish trades, realized performance, returns or strategy labels. Metadata ready is not a private read.

The Worker may only add user triggers to old human tasks and create genuinely useful separate Agent tasks. Existing human text/status/clock/reminder plan and unrelated typed tasks are immutable. A clockless human action needs explicit `waiting` with resume and reason; an existing clock remains a user `time` trigger. The finish postcondition rejects an orphan open legacy card. New tasks require durable Agent triggers, and new actual execution happens in a separate task occurrence with its own restricted tools. No old task is relabelled as a calculation.

`along_source_review_finish` records keep/revise/need_data and specific missing requirements. It seals only planning; it never completes the goal/user action, advances health baselines, schedules a notification or increments executions. Actual separate task results use the existing task detail/result notification path. Existing RunRecord background audit stays `audience: background` and outside user conversation.

Every read/write/finish rechecks goal ownership, active status, input version, paired device, grant generation and source authorization. Same-grant newer metadata is acceptable for this metadata-only review; private task reads separately enforce current revision, reference, freshness and revocation. Stale pending reviews are retired by the runtime, not resurrected by replay. Revocation/new input/new generation cannot write through an old mandate.

Regression: `pnpm exec vitest run tests/along-source-goal-review.spec.ts`. These are scripted synthetic decisions/cache responses through actual Runtime/API/Engine/Sessions/tools, not real-model or phone delivery evidence. They include atomic rollback, pre-upgrade reconciliation, duplicate/revision suppression, restart/backoff, revoked/new-input/device/generation refusals, original clock/typed field preservation, orphan refusal, then actual read and deterministic receipt/count only for a useful new Agent task. Synthetic source numbers must never enter formal personal data.
