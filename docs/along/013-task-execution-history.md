# 动态任务详情的执行记录

本轮上游只提供可核实执行历史的只读投影，不改目标、任务、排程或既有审计，不把 Worker 的执行说明变回聊天。

## 范围与契约

`goalDetail.tasks[]` 和工作区同步快照的任务增加可选兼容字段：

```ts
execution: {
  version: 1,
  count: number,
  records: Array<{
    id: string,
    kind: 'research' | 'completed',
    executedAt: string,
    outcome: 'researched' | 'completed',
    summary?: string,
    recommendationEventId?: string
  }>
}
```

`count` 是全部可信业务事件去重后的总数，`records` 最多返回最新 20 项。标识为宿主生成的不透明稳定键，不暴露工单、模型、工具调用日志。摘要为宿主固定的产品文案。旧客户端可忽略新字段；新客户端不把字段缺失或零解释成「用户未做过」，只表示暂无可核实的执行记录。

这是已确认业务结果的有界投影，不是全部失败尝试的账本。界面用「已记录 N 次执行／暂无可核实记录」限定覆盖范围，不能宣称用户从未执行。资料是否有效按**该次交付时刻**检查：至少一份依据当时有效，部分过期上下文不抹去有效的条件式结果；仅复用全过期资料不补造一次已确认结果。后来天气或路线 TTL 到期仅影响当前推荐可用性，已经确认的历史记录和次数不因此减少。

任务后来合法修订内容也不能改写旧执行的性质：宿主在新结果 outbox 记录交付时的任务修订；旧结果优先使用原通知／到期修订与已发布任务修订，再读取当时版本。研究历史保留 `research`，不会因为当前任务改为实际徒步就消失或变成「已徒步」。该来源标记由宿主写入，不开放模型参数。

## 什么算一次

- 研究任务：同一用户、目标和稳定任务下，正式交付结构化研究结果；来源可追溯至该 Worker 的工具证据。允许合法复用已有来源，不要求每次重新联网。一次业务输入只记一次；同一到期时刻的重试、重新派工也只记一次。
- 实际预约、徒步等行动：只计收到且实际令该任务从非完成转为完成的 `task.completed` 用户反馈事实。计划、排程、Worker ready、`keep`、健康复评、消息条数及任务修订都不是执行次数。单纯模型改成 done 没有该事实，不补造旧执行记录。
- 提醒本身作为任务时，只有真实通知执行／送达回执能证明「已提醒」。目前 Agent 库不持有这种原生送达事实；已预约进系统队列不能算已经执行。Host 如提供此类证据，应与实际行动完成分开，不能把提醒算成已预约或已徒步。
- 已被宿主审计确认为开发／验收来源及其派生记录不计自然业务执行。推荐载体仍可展示在任务详情，历史计数不按推荐卡片数量推断。

## 验收

隔离回归覆盖：正式研究与有效来源复用；同事件多次结果／到期重试／重启不增计；开发来源标记后的投影收敛；真实任务完成事实只记状态转换一次；提醒、复评与排程不充作完成；其他用户或目标不可读取；历史记录多于 20 时总数准确、返回有界。真实个人库只读验证，不为测试写入任务、聊天或执行历史。
