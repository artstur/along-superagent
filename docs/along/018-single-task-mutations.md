# Narrow existing-task mutations

A model can repeatedly serialize nested ChangeSet task revisions as strings and then create replacement tasks instead of modifying the original ones. A strict single-task tool makes the two version layers explicit at the top level without weakening persistence or authority checks.

`along_task_update` accepts `task_id`, numeric task `base_revision`, numeric `goal_revision`, numeric `input_version`, `idempotency_key`, `reason` and the exact existing task.update `fields` schema. `along_task_cancel` accepts the same top-level context without fields. Neither accepts a goal/user/device identity, operations list or a task.create. A host-bound existing goal is required. Calls map to one ordinary ChangeSet operation and reuse the same writer, trigger/plan requirements, authorization, stale-input/revision checks, maintenance scope, human-completion guard and idempotency result. Invalid schema input writes nothing and returns the current owned numeric versions; strings are never coerced. Unrecognized identity/extra fields retain strict rejection.

For an existing single task prefer the narrow update/cancel. Read current goal/task versions, change the original stable ID, keep omitted fields, and read back persistence. A second update re-reads current versions. Multiple related atomic changes and new tasks continue through ChangeSet. This is no new execution engine or creation flow. Existing repair/source-review tool whitelists need not expose these tools; no executor whitelist changes are included here.

Acceptance uses synthetic Runtime/Engine/SQLite/actual registered tools: update two original time tasks while retaining sleep and other fields, no extra task IDs, replay idempotency, cancellation invalidating old result relevance. Reject numeric strings, foreign task/goal, stale goal/task/input versions and background human completion/actor substitution. No production user data, phone, deployed service or real account is touched. Final shared role/prompt allowlists and live-model retest are integration-owner work.
