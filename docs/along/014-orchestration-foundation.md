# Along 目标编排与执行契约

本轮目标：新建目标不能只生成闲置的任务卡。每项可执行任务须有已持久、可由宿主运行的触发方式；缺少事实、授权或能力的步骤须明确等待什么以及如何恢复。规划策略由 Agent 结合目标与环境判断，宿主负责可信来源、权限、版本、幂等和结果校验。

## 审计基线发现的断点（修复前）

- `task.create` 当前只写入任务。没有 `scheduled_at` 的立即 Agent 工作不会自动派工，现有 Skill 又将所有任务说成人的行动。
- 时间到期调度、日／周续排、错过窗口与重启去重已有实现，复用它们，不新增另一个 cron。
- 当前定时工作统一先发提醒，再做研究，缺少 Agent 研究／计算与真人行动的区别。
- 周期授权和完成校验过度绑定少数措辞。真实坏例“周四预约周五瑜伽课”只有单次时间，没有周期计划；修复不能靠界面看到日期就标为定时。
- 来源连接目前只更新 Host 私有状态，没有可持久、去重、撤销的 Agent 触发事件。
- 当前没有确定性计算工具与任务计算结果回执。
- Along Worker 直接拼入两份不断追加的长 Skill，其中旧聊天／通知／来源能力文字与后续修复有冲突；必须统一实际装配入口与按需能力说明。

## 实施顺序

1. **计算能力上游**：受限、可复算的算术工具和绑定任务的结果回执。输入事实与算术正确性分别标明，不允许任意代码执行。
2. **Task Trigger 上游**：类型化执行人／能力与立即、时间、真实事件、可恢复等待；持久发生记录复用现有 Worker 派工与校验。时间继续沿用已有时区／民用钟点规则。事件只接受宿主注册且在同用户、同目标内有权读取的条件。
3. **来源事件桥**：已验证连接／有效摘要保存后产生最小事件，不广播账户数据或凭证；generation、outbox 与重启对账阻止丢事件及断开后的旧 ready 复活。状态查询和按钮点击不是新连接事实。
4. **Prompt／Skills**：系统层保留角色、可信上下文、编排与完成标准；通用目标和任务 Skill 说明业务协议；排期、研究、计算、数据依赖按需加载。运行时能力目录优先于静态厂商说明。
5. **验收**：隔离的新目标真实模型／工具链路与持久状态；受控时钟和故障回放独立标注。正式个人空间只做保全和用户流程验收，不代发测试目标／对话／通知。

## 必须保持的不变量

- 每个任务有可运行 trigger，或有明确恢复事件的等待。`ready` 不等于用户总体目标完成。
- 立即工作须真正进入执行；时间工作须保存下一时刻及日／周规则；事件工作须持久订阅并评估当前条件，而不只等待未来的下一次事件。
- 一次发生只执行／通知一次；取消、改期、撤权与任务修订使旧发生失效。
- 真人行动到点可以提醒，不能据此宣称预约、入睡或徒步完成。Agent 研究与计算按真实工具和已持久结果判定。
- 修改保持稳定任务 ID，只应用必要变更；未受影响字段逐字保留。
- 公开搜索不带个人私密原文，数据读取严格绑定用户／目标／能力。凭证永不进入模型、同步或日志。
- 产品仍只有目标、任务、底部连接数据源；推荐与执行记录在任务详情；后台流水不进入直接聊天。

## 验收矩阵

矩阵与盲输入见本目录后续评测说明及 `evals/along-orchestration/`。至少覆盖：立即计算、跨午夜周期提醒、双课表前一天预约、立即研究与未来天气复查、来源就绪解锁／已有就绪状态、未知能力等待、取消改期、重启去重、多目标隔离、失败不虚报完成。测试的下一轮使用上一轮实际接受状态，不泄露参考轨迹。

## 生效与发布证据

正式发布须核对实际 profile 依赖包、PromptConfig overrides 与实际模型请求的装配内容，不能以仓库文件存在推断生效。记录源 SHA、prompt／skill 摘要、工具调用与持久状态结果。公开样本只用隔离合成目标；实际个人上下文留在私有验收目录。

本文件为实施索引；契约和源码入口在实现过程中同步补齐，不能作为尚未实现能力的对外声明。

## 当前真实实现入口

- `task-trigger.ts` 定义注册的 trigger/capability/condition Schema 和两张持久表。`task-activation.ts` 在宿主 tick 评估当前可信条件，将可运行发生写入原 `scheduled_at` / `task_due` 派工链；它不是另一个定时器。正式 `along_changes_commit` 强制新建任务携带 trigger。旧的未修改任务保留字段和旧定时行为。
- trigger 结构：`kind: immediate|time|event|waiting`、`actor: user|agent`、`capability: reminder|research|calculation`。事件仅支持同目标受权来源、同目标前置任务实际完成、已知健康摘要；等待由实际新用户输入或注册能力恢复继续。时间继续使用 scheduled_at 与 reminder_plan/repeat 的日/周民用时区规则。
- `health.ts` 绑定当前 task/revision/inputVersion/occurrence，提供 `along_task_context`、`along_task_finish`。计算须有当前发生的真实持久回执，研究须有同工单真实来源的结构化结果。普通人类提醒不等于行动完成。
- `calculation.ts` / `calculation-store.ts` 与[计算契约](015-calculation.md)负责确定性算术和可复算回执。`source-state.ts` 与[来源契约](016-source-state.md)负责最小元数据、授权 generation 及私有任务读取；`api.ts`只在原受限桥接通道暴露 source-events/source-reads/source-read-results。
- `inbox.ts` 将周期任务的 task.completed 记录为本次发生完成，保留下周期，重复反馈不增加次数；取消后的延迟完成不能复活任务。只有明确停止才撤销整个周期。
- `reminder_plan.evidence_event_id` 可引用本目标既有、已接受的直接用户授权。宿主查身份、关联、后续拒绝及单次约束；后台修复不生成冒充用户消息或个人聊天。Agent 选择时间仍标 source:agent。
- `task-execution.ts` 只投影有已完成派工、发生、真实工具回执和发布绑定的计算和研究，以及真实用户完成反馈。模型重试、改版、补排和通知入队不增加执行次数。

## 验证口径

`tests/along-task-trigger-runtime.spec.ts` 穿过真实 Runtime/Engine/SQLite/注册工具/API，但由 fixture 驱动模型决策，不能标为真实模型。`tests/along-task-trigger-cadence.spec.ts` 验证前日预约周期、原证据修复、提前完成、两周续排和取消。`tests/along-task-activation.spec.ts` 验证输入、权限、能力恢复及重启去重。盲目标模型执行、Host/App 消费与真机送达分别记录，不以单元测试数替代。
