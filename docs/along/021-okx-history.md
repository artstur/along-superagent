# Private OKX history reports

User-authorized iPhone native code collects fixed official read-only fills and account bills, retains credentials in the same device Keychain, and uploads normalized bounded rows to the paired Host. The Host validates the strict history snapshot and computes exact decimal per-currency/per-instrument report data. This Agent receives only a task-scoped `trading_history` report; source events carry capability metadata, never raw records. The existing `trading_account_summary` path remains compatible.

A ready history report states its fixed observation window, every API stream's complete/truncated/unavailable coverage, counts, exact signed fee cashflows, ordinary derivative trade bill PnL/fee components, separate funding cashflows, small bounded examples and limitations. Report freshness is its windowEnd, not a recent connection time. Unknown/withdrawn capability, source revision/grant changes, cancellation, new input or archive invalidate private reads as before. History output is not automatically full account profit, return, Sharpe, drawdown or strategy efficacy. Spot requires opening cost basis. Fill/bill fees are alternative evidence; do not add both. Different currencies are not summed. Transfers, interest, settlements, liquidation and ADL cashflows are not silently ordinary trading profit. An instrument/tag group does not establish the user's strategy identity; user rules or explicit mapping remain required.

The source schema allows unique registered capability IDs. Schema15 adds the reviewed capability-set to the existing durable source-goal-review row, defaulting historical reviews to the summary capability. New history availability can bootstrap one bounded metadata-only review per source generation/capability set even if the old goal already has typed human tasks. Existing open history subscriptions take precedence. The review can create a separate useful Agent task, never rewrite or complete old human actions, and cannot read private values itself. No fake user message or new framework is introduced. Repeated ready revisions/restart do not duplicate a review.

A task first reads `along_task_context`, then `along_source_read` with `capability:"trading_history"`. The existing Host-bound identity/task/revision/input/occurrence and freshness checks apply. Pending/stale/unavailable remains durable Host waiting; no model polling loop or manufactured empty dataset. Only ready data with matching windowEnd is usable. A typed private-history research task finishes with its actual source_request_id and qualitative text; the Host renders a fixed numerical fact segment from that report and binds completion/history to the same occurrence. It does not fabricate web citations or relax public recommendation evidence. Report fields already contain deterministic aggregation; the general calculator does not accept arbitrary history paths as scalar evidence. Model explanations must quote the actual report and its limits. Private raw fields/IDs/tags never enter public search, logs, notifications, memories or ordinary automatic audit notes.

Acceptance uses isolated Runtime/API/registered tools: legacy summary review followed by new history, preserved human tasks and count0, one history review, actual ready read, saved researched result/count1, duplicate/restart idempotence, summary compatibility and revoke/foreign-scope rejection. Full repository typecheck/test/build and actual phone/model acceptance are distinct evidence.

Companion contract: Along `docs/okx-trade-history.md`. Official semantics: [API guide](https://www.okx.com/docs-v5/en/), [pagination](https://www.okx.com/docs-v5/trick_en/). Async downloadable archives requiring POST remain outside this GET-only iteration.
