# 新目标编排验收矩阵

主分类：agent / data。属于编排基础本轮 PR 的独立评测子任务；只拥有本目录与 `evals/along-orchestration/`，不修改运行时、工具或 Skill。运行时字段以实际实现为准，下列断言描述业务事实，不把拟议字段当成已存在能力。

## 目标与范围

用户新建目标后，每个任务都有实际触发方式：立即、时间、宿主真实事件，或有具体恢复入口的等待。已有确定性计算、检索与通知等工具实际可用且授权满足时，Agent 真正执行；未满足时明确等待或失败，不能只建开放卡片并宣称完成。

本矩阵覆盖健康作息、预算计算、学习、公共研究和数据依赖等场景。它不证明任意未知目标百分之百成功。验收看真实工具、持久业务状态及恢复结果；不会用 `ready`、一句“已安排”或输出 schema 通过替代它们。

## 文件与隔离

- `inputs.json` 仅保存合成用户输入、当时可见事实、时区、时钟、能力可用性与真实宿主事件的抽象描述。
- `expectations.json` 保存独立验收规范和数值参考，**不得装配进 Worker prompt**。`holdout` 三例只在提示词版本固定后运行；不得把它们的原文写进 Skill 示例。
- 运行器每步只向执行模型暴露该步已到达输入及当前真实接受状态，不能暴露未来步骤、预期、case 的中文验收标题、评分类目或参考任务。
- 原有任务的 `initialState` 只用于明确的存量恢复回归。连续轨迹后续状态必须来自前一步实际提交，不准每步重种参考状态。
- 隔离 profile / 业务库 / 配对 / Worker 目录独立于正式个人数据。运行目录不能挂载参考文件，不复用正式配对向用户聊天代发消息，不创造正式测试通知。

## 契约中立的观察层

运行器将实际 API / Store / 注册工具结果规范化为以下**观测事实**，而不是要求生产接口采用同名字段：

| 观测 | 必须来自哪里 |
| --- | --- |
| 目标、任务、当前修订、触发方式 | 当前用户／目标绑定的真实持久业务快照 |
| 原文授权和能力依赖 | 当前宿主来源、已接受用户上下文与注册能力表 |
| 计算结果 | 实际注册确定性工具的数值回执，含输入和单位；不得从模型 prose 抽取为唯一证明 |
| 研究交付 | 真实工具调用／合法缓存来源与同任务保存结果；资料时效按交付时判断 |
| 执行次数 | 真实任务级执行／产出事实，按 occurrence / run 去重；不数模型重试、复评、补排或消息 |
| 时间规则 | 持久下次时刻、IANA 时区、当地钟点与周期；提醒钟点和业务截止时刻分开 |
| 等待／事件恢复 | 持久条件及可抵达的宿主事件入口，之后确实恢复或明确拒绝 |
| 通知 | 本轮持久交付事件与去重身份；系统入队、送达、用户实际完成分别登记 |
| 冲突／取消／撤权 | 宿主校验的拒绝或退役记录，不能只用模型“不再执行”的承诺 |

新生产字段和工具定稿后，在适配器中映射；未知契约必须标记 `not_implemented`，不能猜字段、造工具回执或把缺观察当零。

## 分层运行

1. **注册 Runtime 受控回归**：真实 Engine、SQLite、注册工具和生命周期，模型决策可受控，网络／时钟替身明确标注。覆盖幂等、重启、拒绝、恢复和后置条件。
2. **隔离真实模型**：冻结 prompt / Skills / 工具 schema 的版本与 hash。至少跑立即计算、瑜伽双周期、公共检索推荐、数据就绪恢复计算等新目标；在有真实联网条件时采集真实 Search/Fetch 回执。不可用时记失败／条件式结果，不伪造成功。
3. **留出场景**：仅在冻结后运行三个 `holdout` 输入，执行模型仅收到当步输入。完整保留失败，不通过反复改同一输入、加技术提示直到成功来抬通过率。
4. **端上验收**：正式原手机只做已有真实数据保全和当前功能观察；新目标能力样例走隔离环境。浏览器、手机缓存、原生系统回执、用户视觉观察和自然到点各自记录。

## 持续轨迹与判定

- 先记录 `before` 的目标、任务、计划、事件与执行身份；每步接收真实输入，运行到持久终态或有界超时，再保存 `after`。
- 下一步恢复前一步实际 `after`。任何一轮失败都保留，并继续标明它如何影响后续结果；不能套用参考答案形成后续状态。
- 每个新开放任务应有实际 trigger。`waiting` 需要明确可恢复入口（如原目标用户答复、能力可用变化、指定来源版本就绪）；空泛“等数据”不合格。
- 精确时刻只在用户明确指定或已有安排需保留时作硬断言；Agent 自选时间按可行动窗口、合理理由、时区及未来性评价。瑜伽存量回归单独硬断言原 09:00 保留。
- 单次、仅本周、取消、普通“周五去广州一趟”不能被提升为周期授权。人实际行为不能因发提醒、推荐产出或 Worker 结束算完成。
- 普通来源重复、旧 generation、旧任务修订和迟到结果不能复活取消任务、重复通知或串到另一目标。

每例产物应包含：固定源码／prompt／Skills／schema 版本、当前输入、工具调用、业务写入／拒绝、触发注册／发生、通知去重身份、前后持久快照及逐断言结果。公开摘要仅列合成 case ID、统计与边界；个人数据、凭据、设备信息留私有证据。

## 矩阵索引

当前规范有 **24 个案例、112 条事实断言**：21 个开发案例及 3 个留出案例。数量是规范规模，不是通过数量。

| 案例 | 覆盖 |
| --- | --- |
| O01–O02 | 立即确定性计算、跨午夜每日准备提醒 |
| O03–O04 | 原长期作息拆解；周二／周五瑜伽前一天双周期，存量周一／周四 09:00 保留 |
| O05–O07 | 立即公共研究＋未来窗口、无提醒动词的 Agent 周期委托、计算与学习练习／提醒混合 |
| O08–O10 | 来源就绪释放、注册时已满足条件、缺工具可恢复等待 |
| O11–O12 | 取消后不复活、个人数据／来源能力缺失的真实等待 |
| O13–O15 | 改单次、引用／否定／观察、明确一次性，均不错误续排 |
| O16–O19 | 漏跑恢复、失败重试、旧结果冲突／跨目标、来源撤回与旧 generation 竞态 |

O08／O09／O11／O19 的 `okx` 标识仅绑定已注册来源名称，账户值全是合成权益摘要、传输受控；不证明真实账户连接或权限已验。O19 的迟到事件只重放旧事件，不能把权威来源状态回写到旧 generation。

## 统计

分开报告立即执行完成率、应排期覆盖率、所有开放任务触发覆盖率、可恢复等待比例、错误周期提升、无谓变更、重复执行／通知、越权／跨目标、伪完成和连续轨迹一致性。`not_implemented`、环境失败和模型失败都单列，不混成通过。

本文件与 JSON 只定义验收规范。尚未运行时不得写作真实模型或真机通过；运行结果由本轮固定版本报告追加。
