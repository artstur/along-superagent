---
name: dsh-superagent-along-task
description: Create and adjust Along user tasks after goal intent is established; handle constraints, chat feedback and changes to an existing plan.
---

Read the goal and existing tasks before planning. A user task is an action for the person; a DSH Ticket or Assignment is agent execution and never belongs in that list.

For a new goal, submit a small useful next step together with `goal.create`. For an existing goal, use stable task ids and revisions to update or cancel rather than copying tasks. Carry temporary constraints in goal context with an expiry when known. Preserve explicit priorities and hard constraints. Ask one specific question only when missing information changes the next step.

Submit related operations as one validated `along_changes_commit`. Do not request adoption. Completion feedback is a fact; it is not permission to change the goal. A correction supersedes the older plan: re-read the current conversation and task state before retrying.

For every new task decide its reminder in the same commit, including tasks suggested by you. Read the user timezone and current time from along_conversation_read. A deadline, session and reminder can be three different instants.

- An executable time-bound action with a usable window gets a future ISO scheduled_at with an offset and reminder_plan {state:"scheduled",source:"agent",explanation:"…"}. Choose a reasonable local time to make the action possible. Describe the reason and any lead time. The host puts your arrangement in the conversation. When the user specified the reminder clock itself use source:"user" and include exact evidence quoting that instruction. A deadline or a class time alone does not specify a reminder clock.
- “周二和周五上课，前一天要预约” → schedule the next Monday/Thursday booking action first, at a sensible time on the preceding day. Explain your choice. One task per distinct booking action if needed. If a release window materially determines when booking is possible and is genuinely unknown, use {state:"needs_time",question:"…"} naming the missing window. The host sends that question to chat; do not duplicate it via along_chat_reply. Do not require a user to configure each clock.
- “每天凌晨2点前入睡” gives a sleep deadline. Choose an earlier actionable winding-down time as an Agent arrangement for the next occurrence. Only mark a recurring reminder when there is a task-specific continuing mandate. Never call the chosen lead time user-specified. Ordinary untimed ideas use {state:"off",reason:"untimed"}; a declined reminder uses reason:"opt_out".
- repeat:"once" (default) does not renew. For an explicitly ongoing schedule set repeat:"daily" or "weekly", reminder_plan.evidence to the exact user clause authorizing that action and reminder_plan.action to its distinctive action text present in both that clause and task.content. Weekly uses the local reminder weekday, not the class day: “每周一上午提醒我预约周二的课程” binds Monday. Separate different weekly actions. A request at the end of a list to arrange its tasks and reminders applies to the listed recurring actions. For “我想每周二和周五上陶艺课，前一天要预约。每天凌晨2点前要收拾完画具。请帮我安排任务和提醒，具体提醒时刻你来安排”, create two distinct weekly booking tasks (e.g. “预约周二陶艺课” / “预约周五陶艺课”); cite the exact course/preceding-day phrase as evidence and “陶艺课” as the shared action, with reminders on Monday and Thursday. For the daily action, keep “收拾完画具” in both the quoted daily clause and task content and schedule an earlier useful time as source:"agent". Without a defensible ongoing mandate arrange the next occurrence once.
- Adjust the same task ID with its latest revision. task.update.fields.reminder_plan:"keep" preserves a previously verified plan when rewording the same action. When the time changes submit a complete replacement plan and future scheduled_at. Turn off a reminder without cancelling the task by setting reminder_plan:{state:"off",reason:"opt_out"}. Complete/cancel through existing task operations. Never start or renew reminders that the user declined.

For a requested recommendation now ready in an active goal, deliver it with along_chat_reply and notify:"recommendation_ready". For an actionable result use notify:"task_result". Include task_id only when verified. Routine planning and clarification do not produce extra alert notifications. A host-bound due review reads current state, then completes with along_health_followup. Already-bound daily/weekly mandates renew on ordinary keep. Never introduce recurrence from a due tick.


When current external facts or recommendations are necessary, read dsh-superagent-along-research; for hiking also read dsh-superagent-along-hiking. Use the Along web tools to obtain scoped citations. An existing task to research a destination executes that research when due through along_health_followup with its structured recommendation. Do not replace it with a generic reminder to research.
