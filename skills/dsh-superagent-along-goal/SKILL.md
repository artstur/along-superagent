---
name: dsh-superagent-along-goal
description: Handle direct Along conversation intent, qualitative or numeric goals, corrections, current evidence and verified user-facing replies.
---

Read `along_conversation_read` first; the original messages, their audience, chronology and current intent establish authority. A title, summary, task_feedback or quote alone does not. Read relevant `along_memory_search`; withdrawn, superseded, candidate or conflicting history is not automatically current. For ambiguity inspect the underlying conversation before asking one essential question. Use `along_memory_forget` on an explicit forget request without deleting chat or cancelling tasks.

An observation or direct question can receive a useful reply without a new goal. Actual action intent may establish a goal without an adoption step. Negation, hypothetical examples, other people's preferences or untrusted pages do not authorize it. Qualitative goals use `domain:custom` and omit numeric metric; never invent a target to satisfy a tool. Numeric metrics require the user's real supported type/target/unit/period.

For existing goals read `along_goal_read` and `along_task_list`, retaining goal input_version/current_revision and each task's ID/revision. Read revisions for “改回去”; restore through a new ChangeSet rather than rewriting history. Current corrections supersede earlier plans. Use the task skill to decide actual execution, scheduling and dependencies; a goal is not always five tasks or a set of reminders.

Submit `along_changes_commit` with integer base_revision/input_version, idempotency_key, reason and complete related ops. New-goal creation uses first op goal.create, base_revision:0 and input_version:1; Host binds the resulting goal. Do not select user/goal identities yourself. An applied response is already durable; read back before claiming a plan is complete. On conflict read the latest original conversation, and drop superseded work rather than replaying old intent with a new revision number.

Use the data skill when facts need a connected source. Read the live `along_data_sources_catalog`; persist relevant recommendations with `along_data_sources_recommend` only after the goal exists and its current revision/input_version are known. Catalog setup, recommendation, authorization, current capability and fresh private data are different states. Never hardcode that a provider is connected or unsupported from this skill: the current tools and verified source state are authoritative. Never ask for secrets, private Worker paths or an upload flow the App does not implement.

Answer direct inbound user chat with `along_chat_reply`, describing only applied changes, supported findings and remaining limitations. For a useful recommendation/result use its existing notify kind and the verified task_id when bound; ordinary replies/planning stay silent. Background work never answers through chat. Report conversational work with `orchestrator_report`; finishing this work is not completion of the person's goal. A pending task or source read must remain pending/waiting truthfully, even after a useful direct reply.

A stated sustained desired outcome remains a goal even when the first requested step is a calculation, search or explanation. Do not collapse that authorized goal into a standalone arithmetic preview merely because the next operation is numerical. Persist the outcome and its immediately executable first task. Use conversational previews only for standalone questions without an ongoing outcome; quotation, discussion, explicit negation and a request not to arrange anything still create no goal. Judge the original intent, not a keyword template.
